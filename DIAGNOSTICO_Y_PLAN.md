## 🚨 Hallazgos Críticos

### 1. VULNERABILIDAD DE SEGURIDAD: API Key expuesta al cliente

> **⛔ CAUTION**
> La API Key de DeepSeek se almacena en `localStorage` del navegador y se envía en cada request del body JSON al backend. Cualquier usuario puede inspeccionarla desde DevTools. Esto es una **vulnerabilidad crítica**.

**Archivos afectados:**
- `src/app/page.tsx` L14-L16 — Estado `apiKey` en el cliente
- `src/app/page.tsx` L157 — Lectura de `localStorage`
- `src/app/page.tsx` L412 — Escritura a `localStorage`
- Todas las rutas API reciben `apiKey` desde el body del request

**Solución:** Migrar la API Key a una variable de entorno server-side (`.env.local` con `DEEPSEEK_API_KEY`) y eliminar completamente el manejo de API Key del frontend.

---

### 2. ARCHIVO MONOLÍTICO: `page.tsx` con 2,312 líneas y 128KB

> **⚠️ WARNING**
> **Todo el proyecto** vive en un único archivo `src/app/page.tsx`. Esto incluye: lógica de negocio, estado global, 30+ handlers, parsers de prompts, y todo el JSX de 5 pestañas completas. Esto es insostenible para mantenimiento, testing y colaboración.

**Impacto:**
- Imposible hacer code splitting efectivo
- Re-renderizado innecesario de todo el dashboard en cada cambio de estado
- Colisiones de merge garantizadas en equipo
- Zero reusabilidad

---

### 3. NOMBRE ENGAÑOSO: `gemini.ts` usa DeepSeek, no Gemini

> **ℹ️ IMPORTANT**
> El archivo `src/lib/gemini.ts` se llama "gemini" pero **solo** llama a la API de **DeepSeek**. Esto genera confusión severa para cualquier desarrollador que ingrese al proyecto.

---

### 4. DATOS HARDCODEADOS en la pestaña de Métricas

La pestaña "Métricas de Crecimiento" (`page.tsx` L2065-L2141) muestra datos **completamente hardcodeados** (42.3k seguidores, 3,124 DMs, 245k alcance, 5.8% engagement). El usuario ve datos falsos sin indicación alguna de que son ficticios.

---

### 5. INCONSISTENCIA DE IDENTIDAD: Migración fantasma `Valeria Cruz → Milena Basset`

El código conserva el ID `"valeria_cruz"` como identificador del avatar principal (`db.ts` L57) y ejecuta una migración forzada en cada carga (`page.tsx` L174-L191), sobrescribiendo campos del avatar cada vez que el usuario recarga. Si el usuario editó su avatar, pierde sus cambios.

## ⚠️ Hallazgos de Prioridad Alta

### 6. Sin manejo de errores de red robusto
- Las llamadas `fetch` al API solo verifican `response.ok` pero no manejan timeouts, desconexiones, o errores de red
- No hay retry logic en ninguna llamada a DeepSeek
- Las respuestas JSON de DeepSeek se parsean sin validación de esquema (`JSON.parse` directo)

### 7. `navigator.clipboard.writeText` sin fallback
La función `triggerCopy` (`page.tsx` L425-L429) usa `navigator.clipboard.writeText` sin `try/catch`. Esto falla silenciosamente en contextos HTTP (no HTTPS) o en iframes sin permisos.

### 8. Imágenes base64 en localStorage
Las fotos de perfil y productos se almacenan como strings base64 completos en `localStorage`. Con límites de ~5-10MB de localStorage por dominio, una foto de 2MB con su overhead base64 (~2.7MB) puede llenar la cuota rápidamente, especialmente con múltiples avatares.

### 9. `confirm()` nativo del navegador
Se usa `confirm()` nativo de JavaScript (`page.tsx` L386) que bloquea el hilo principal y no puede ser estilizado. Rompe completamente la estética premium de la interfaz.

### 10. Scroll del chat sin `scrollIntoView`
`chatEndRef` (`page.tsx` L80) se declara pero **nunca se invoca** `scrollIntoView`. El chat no hace auto-scroll cuando llegan mensajes nuevos.

### 11. Metadata SEO genérica
```typescript
// layout.tsx L15-18
export const metadata: Metadata = {
  title: "Create Next App",          // ← Título genérico del boilerplate
  description: "Generated by create next app",  // ← Descripción genérica
};
```

### 12. `next.config.ts` completamente vacío
```typescript
const nextConfig: NextConfig = {
  /* config options here */
};
```
Faltan configuraciones esenciales: headers de seguridad, compresión de imágenes, dominio de API externa permitido, etc.

## 🟡 Hallazgos de Prioridad Media

### 13. Tipo `any` excesivo
Múltiples usos de `catch (error: any)` en todo el proyecto. TypeScript pierde toda capacidad de type-checking en manejo de errores.

### 14. `handleUpdateProductInfo` con `null as any`
```typescript
// page.tsx L637-639
if (image === null as any) {
  delete updatedIdea.productImage;
}
```
Hack de tipos que evade el sistema de tipos de TypeScript.

### 15. IIFE innecesarios en JSX
En la pestaña de chat (`page.tsx` L1876 y L1984), se usan funciones auto-invocadas `(() => { ... })()` dentro del JSX para encontrar la simulación activa. Esto debería ser un componente separado o un `useMemo`.

### 16. Archivos SVG de boilerplate sin usar
Los assets `file.svg`, `globe.svg`, `next.svg`, `vercel.svg`, `window.svg` en `/public` son del template de Next.js y no se usan en la app.

### 17. Instagram.md con contenido obsoleto
El archivo `Instagram.md` referencia a "Valeria Cruz", "finanzas", "inversiones" y enlaces de afiliados — conceptos que ya fueron eliminados de la identidad actual (Milena Basset = Lifestyle de Lujo).

### 18. `GrowthPhase` no se usa realmente
El tipo `GrowthPhase` (`db.ts` L20) define 3 fases (`storytelling | value | conversion`) pero en la práctica siempre se envía `"storytelling"` hardcodeado (`page.tsx` L485).

### 19. `font-family: Arial, Helvetica, sans-serif` sobrescribe la fuente Geist
En `globals.css` L25, se usa `font-family: Arial` en el body, lo cual sobrescribe la configuración de fuente Geist del layout. El font-family debería usar `var(--font-geist-sans)` o eliminarse para dejar que Tailwind maneje la tipografía.

### 20. IDs no semánticos para generación de datos
Los IDs se generan con `Date.now()` (`page.tsx` L347, L502). Si se generan dos en el mismo milisegundo, colisionan. Se debería usar `crypto.randomUUID()`.

## Preguntas Abiertas

1. **¿Deseas mantener el sistema multi-API Key en el frontend?**
   Si tu intención es que cada usuario ingrese su propia clave DeepSeek (modelo SaaS BYO-Key), la arquitectura cambia. En ese caso, la key se debería cifrar antes de almacenarla y transmitirla, o usar un proxy seguro.

2. **¿El sistema de fases de crecimiento (`storytelling → value → conversion`) se va a implementar?**
   Actualmente todo está hardcodeado a `"storytelling"`. Si se planea implementar las 3 fases, lo incluyo en el plan. Si no, elimino el código muerto.

3. **¿Las métricas de la pestaña 5 serán conectadas a datos reales (API de Instagram/TikTok)?**
   Si sí, necesito saber la fuente de datos. Si no, las marco como "demo" con indicador visual.

4. **¿Quieres que implemente la refactorización completa en componentes (Fase 2) o prefieres solo las correcciones críticas (Fase 1)?**
   La Fase 2 es un cambio masivo pero fundamental para la mantenibilidad a largo plazo. Puedo hacerla incremental.
